# Pick — selecting inside a baked frame

Tapping a poemfield puts the whole world down as `PNT` commands, and from that
moment it is **baked**: the ink is there and the identity is not. You cannot ask
the frame for the building, because the frame has never heard of a building. The
same is true of a drawn stroke, a stamped photograph, an imported clip —
everything arrives as levels, and levels have no parts.

`Pick` is the fifth tool, beside Pen / Box / Erase / Clear. Tap the board and it
selects a piece of what is already there.

## two ways back to the parts, kept because they fail oppositely

**The provenance, when it exists.** A world knows which part drew every cell, so
a stamp brings that map down with the ink — downsampled the same way, the winner
of each max-pool giving its owner. Tap a window and you get **every window in the
city**, across all six towers, because `windows` is a real thing and not a blob
that happens to be window-shaped.

    PICKED WINDOWS   →  LIFT · COPY · CUT · DONE
    TAKEN OUT        →  the towers, the waterline and the clipLine untouched

**The shape, always.** With no map — a hand-drawn frame, an imported clip, a
world that names nothing — the tap floods across connected ink and takes that
region. A worse handle, and available on every frame there will ever be.

## what you can do with a selection

Drag it, and it moves — the old cells are lifted to level 0 and the new ones
written, as ordinary commands, so it is an edit like any other and branches and
exports the same. `COPY` leaves the original. `CUT` takes it out. `LIFT` turns
the selection into a **placement**: a floating image you can size, turn and put
down anywhere, which is the bridge from picking to collage.

The owner map moves with the selection. Without that, moving the windows once
would leave the map pointing at where they used to be, and the second pick would
grab the hole.

It is held in memory only. A film has to stay a film: the map is a convenience
for editing this session, not a fact the `.twinstrip` carries.

## a caching lesson, twice

A module URL is cached hard — three engine fixes were live on the server and
invisible in the browser, which is why `HW_BUILD` exists. Then the **page** did
the same: the Pick button was in the HTML and absent from the DOM for a full
test round. Neither is a bug in the code being tested, and both cost real time
before I stopped believing the browser.
